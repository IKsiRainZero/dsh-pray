# dsh-pray · 期待

> 一个本地单机的 DeepSeek Harness 增量小游戏：五层 **Level**、**愿力**、**催更**、**发版**、**释怀**，以及**注意力保护模式**。
>
> 无账号、无排行榜、无总仓库、无遥测；所有数据都在本机 `$DSH_HOME/dsh-pray/`。

**v0.6.3**：升级进度条加大到 9px/12px，并用 1.15s 缓动平滑过渡。新增 **知识地图**：25 条 seed 条目，分 DSH 组件/机制与 AI 全景，可展开、标记已读、显示阅读进度；内容数据在 `game/story.js`，随学习/产出更新。

## 首先：它不想要你的注意力

- 第一次打开会弹一次说明，标题就是 **「首先」**。
- 默认 **注意力保护模式**：自动买 Level，不自动催更/发版/释怀；到可释怀时暂停购买。
- 右下角完整卡片：`−` 收成一簇**燃烧的小火苗**（hover 显示简要面板，移开消失），`×` 关闭；关闭后从侧栏「期待」页头或设置里重新打开。火苗/卡片本身是 fixed，不占页面布局。
- 设置里可以切到 **游玩模式** 手动购买，也可以切换完整卡片/火苗。
- 只读会话数、完成轮数、活跃时长这些数字，不读聊天内容。

## 五层 Level 与层内注脚

| Level | 名字 | 解锁（累计期待） | 基础成本 | 每 10 个成本倍率 | 注脚 |
|---|---|---|---|---|---|
| 1 | 期待下次更新 | 0 | 1 | ×1e4 | SemVer 语义化版本 |
| 2 | 别打扰梁叔叔搞AGI | 1,000 | 10 | ×1e5 | AGI 与 MoE |
| 3 | 谁给ds报名的憋气大赛？ | 100,000 | 1,000 | ×1e6 | 延迟与吞吐 |
| 4 | Pro来✋🏻😡🤚🏻 | 10,000,000 | 1e5 | ×1e7 | 训练与推理 |
| 5 | 我们的deepseek···会变成什么样子 | 1,000,000,000 | 1e7 | ×1e8 | 缩放定律与涌现 |

每层买 10 个，产出 ×1.2；每个 Level 有独立吞吐上限（1e7 / 1e6 / 1e5 / 1e4 / 1e3），所以速度不会无限跑飞，但期待本身没有硬上限。所有 Level 始终列在 Level 页里，中间是拥有量/已买/本层累计产出/购买倍率/速度，右边是 +1 / +10 / MAX。**注脚在「故事」页**，不在 Level 行里。

## 催更 / 发版 / 释怀

| 层 | 动作 | 代价 | 重置 | 留下 |
|---|---|---|---|---|
| 1 | **催更** | 期待，首价 10,000，×100/次 | 所有 Level | 催更次数（每层 +2% 加法，发版时清空） |
| 2 | **发版** | 3 + 已有发版次数 次催更，外加期待（首价 1e6，×100/次） | 催更、所有 Level | 发版次数（每层 +5% 永久加法） |
| 3 | **释怀** | 本轮累计期待 ≥ **1e12** | 期待、Level、催更、发版 | 愿力、释怀、成就、档案、本层累计产出 |

- 释怀收益 `floor(sqrt(本轮期待 / 1e12))`；永久加成是 **`2 × (1 - exp(-release / 20))`**，最高 +200%，不再让一次大释怀把永久倍率顶到几百万。
- **没有期待硬上限**：每层产出有吞吐上限（见上表），速度自然饱和；期待可以继续增长，只是越来越慢。当前 attention 自动购买的理论首次释怀时间约 **17.8 小时**（1 次购买/秒、无手动重置）；手动催更/发版会更快，实际区间还要继续实验。
- 催更/发版/释怀都要求二次确认；第一次释怀有全屏特效，设置页可预览。
- 当前 live 存档是 v0.4.0 的跑飞遗留（`release` 很大）；设置页有 **修复存档**，会把释怀倍率归零，保留愿力/成就/档案。

## 倍率的区别

- **永久加成（加法）**：释怀（缓和曲线）、成就（每项 +2%~5%）、发版（+5%/次）、专注习惯（+5%/级）。
- **临时加成（加法）**：版本红利（24h，+25%）、等待加成（最多 +50%）。
- **本轮加成（加法）**：催更（+2%/次，发版清空）。
- **总倍率** = `1 + 永久 + 临时 + 本轮`，不累乘；UI 里会分开显示。

## 愿力与长期习惯

- 新开一个用户根会话 +1；每日首个会话额外 +3；
- 完成一轮 +1；每活跃 10 分钟 +1；连续天数 +1~5/天；
- 子 agent 只统计“分身”，不给愿力；token 与成本只进档案；
- 每日上限 30（回声习惯 +3/级）。
- 长期习惯（愿力购买）：**专注习惯**（期待 +5%/级，加法）、**回声习惯**（愿力 +3%/级、上限 +3/级）、**离线习惯**（离线上限 +1h/级）。

## 故事与知识地图

- **故事** 页按 Level 解锁五章，并把每层的术语注脚一起放进去。
- **知识地图** 页分两类：
  - **DSH 组件与机制**：Session、Turn/Step、Tool、Slot、Plugin/Bundle、Profile、Workspace、Context、Skill、Hook、Sandbox、MCP。
  - **AI 全景**：Token、Embedding、Transformer/Attention、Context Window、Pretraining、SFT/RLHF、Inference/KV Cache、Quantization、MoE、Scaling Laws、Agent/Tool Use、RAG、Evaluation。
  - 每条可展开，标记已读；有阅读进度条；数据在 `game/story.js`，当前是 seed 版，随学习/产出更新。
- **成就** 是本地永久小加成（加法），例如第一次释怀、解锁 Level 3/5、10 个会话、100 轮、连续 7 天、10 次催更、3 次发版；不要求花钱。
- **纪事** 自动记录 DeepSeek 更新日志的日期与标题；版本红利给 24h +25%。

## 数据与隐私

| 文件 | 内容 |
|---|---|
| `$DSH_HOME/dsh-pray/state.json` | 期待、Level、催更、发版、愿力、释怀、成就、档案、更新日志缓存、纪事 |
| `$DSH_HOME/dsh-pray/aggregate.json` | **v0.1 遗留**，v0.5 不再读写；可手动删除 |

- 只监听 DSH 核心事件：`session/created`、`session/event`、`session/disposed`。
- 只存数字聚合：会话数、完成轮数、活跃秒数、连续天数、工具调用数、token 数；不存 prompt、回复、文件路径、账号或密钥。
- 除抓取官方更新日志外，不联网、不上传、不读 `dsh-context` 的数据库。
- 设置页提供「导出本地数据」；删除 `$DSH_HOME/dsh-pray/` 即可清空本地数据。

## 安装

### 从 GitHub 安装（当前推荐）

仓库：<https://github.com/IKsiRainZero/dsh-pray>

```sh
dsh plugin --profile <profile> add github:IKsiRainZero/dsh-pray
```

本插件没有构建脚本；装完重启 profile 即可。

## 开发

- 纯 JS，无构建步骤；Host 只用 Node 内置模块，Client 只用 `window.__ModuleLoader__` + React。
- 数值表：`game/balance.js`；纯函数引擎：`game/engine.js`；行为采集：`game/activity.js`。
- 测试：`node test-engine.mjs`、`node test-host.mjs`。

## 已知限制

- **v0.4 → v0.5 迁移**：移除 `runAmps`；旧式每层放大项不再存在；`boosts/galaxies` → `urges/launches`。
- **v0.2 → v0.5**：三维度 A/B/C 映射到 Level 1/2/3；旧 run amps 丢弃。
- **v0.1 → v0.5**：旧 `points` 变成 `expectation` / `lifetimeExpectation`。
- **没有反作弊**：本地 JSON 可改，开源即接受。
- **数值仍在调**：1e12 释怀门槛、催更/发版成本、吞吐上限、注脚内容都可能随体验调整。
- **挑战关卡还没做**：这版先做了层内注脚、成就、故事、注意力保护；限制条件 + 独立重置的挑战系统留到下一版。

## 兼容性

- 当前验证环境：DSH Desktop `0.2.1-rc.3`，profile `desktop`，Web GUI。
- `engines.dsh`: `>=0.2.1-rc.1 <0.3.0-0`。
- 上游每发一个新的 `0.x.y` 元组，需要重新核对 semver range。
